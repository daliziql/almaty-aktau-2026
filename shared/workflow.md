# 攻略生产标准流程（shared，持续迭代）

> 版本：v0.1（初始化）。每次迭代在文末追加记录。

## 阶段 0 · 明确需求（产出 `00-需求与约束.md`）

- 目的地、出行日期与天数、出行人（人数/是否有老人小孩）
- 预算区间、交通偏好（飞机/高铁/自驾）、住宿偏好
- 兴趣标签（自然风光/美食/人文/徒步/拍照/躺平）与体力上限
- 硬约束（必须去/绝对不去、饮食禁忌、请假窗口）
- 模糊项先标注「待确认」，不自行编造默认值

## 阶段 1 · 素材采集（存入 `raw/`，保留出处）

按「内部优先、公开补全」顺序：

1. **企业知识搜索**：用完整自然语言提问，一次性合并多个内部子问题，例如
   「同事们关于 XX 目的地的行程安排、景点推荐、美食住宿、踩坑经历和旅游攻略文档有哪些？」
   —— 拿到群名、文档标题、链接与摘要。
2. **飞书 IM 精确采集**（对重点旅游群）：
   - `+chat-search --query 旅游/目的地` 定位群，拿到 chat_id；
   - `+chat-messages-list` 按时间线拉取讨论；
   - `+messages-search --query 关键词（避坑/门票/酒店/堵车…）` 跨群补漏；
   - 群内分享的攻略文档链接登记到 `sources.md`。
3. **文档本体读取**：对攻略文档用 lark-doc / lark-wiki 读取全文，导出快照到 `raw/`。
4. **公开信息补全**：门票预约规则、营业时间、交通票务、天气、最新政策（general_search + web.fetch），
   内部经验与公开事实在笔记中分开标注来源。

## 阶段 2 · 经验提炼（产出 `notes/`，遵循 extraction/红黑经验提炼规范.md）

- 按「行前准备 / 交通 / 住宿 / 餐饮 / 景点玩法 / 购物消费 / 安全与应急」分类
- 每条经验记录：内容、红/黑属性、来源（谁、在哪个群或文档、时间）、适用条件
- 多人交叉印证的经验标注「多人验证」；孤证标注「单源待核」并尽量用公开信息核验

## 阶段 3 · 行程框架（从 templates/行程攻略模板.md 复制为行程目录下的 `行程攻略.md`）

- 先搭天级骨架（每日区域 → 景点串线 → 交通衔接 → 餐宿），再填细节
- 红黑榜嵌入对应日程，同时在攻略末尾汇总总红黑榜
- 时间/距离/票价等关键数字必须来自素材或可核验来源，算不清就标「待确认」

## 阶段 4 · 校验成稿

- 回读检查：每日动线是否顺路、时间是否可行、预约/门票是否有前置要求
- 每条红黑经验是否都有来源；预算合计用工具计算，不口算
- 输出：最终 `行程攻略.md` + 一份给用户的关键结论摘要

## 阶段 5 · 出行后复盘（驱动 shared 迭代）

- 实际 vs 计划：哪些判断对了、哪些踩了没预料的坑
- 新增红黑经验回注；模板/规范缺什么字段就改 shared，并记录迭代

## 迭代记录

- v0.1（2026-08-31）：初始化五阶段流程与目录约定。
- v0.2（2026-08-31，哈萨克斯坦行程复盘式补记）：
  1. **时区/政策必须核验到最新**：旧攻略可能沿用过时时区（哈国 2024 年才全境统一 UTC+5），阶段 1 增加「目的地近年政策变更核验」动作，官方来源优先（使馆/总领馆/政府公告）。
  2. **航段倒推法**：固定起降时刻先倒推「最晚到机场时间→当日活动截止时间」，再向前排日程；内陆段按「班期表（周几有哪班）」而非「航线存在」排程，廉航单列行李/选座成本。
  3. **多目的地不连续飞行**：飞行日之间必须隔完整游玩日；当活动天数吃紧时，用「方案对比表」显式列出红眼/砍项/强度的取舍，不替用户静默牺牲。
  4. **体力相邻性检查**：两个徒步/高强度项目相邻时必须标注并给出对调或降级方案；野外日预留「夜返市区睡床 vs 营地等日出」的明确选择。
  5. **同一酒店连住寄存大件**：多段往返同一城市时，固定一家酒店寄存主行李，分包出行，写入阶段 3 排程规则。
