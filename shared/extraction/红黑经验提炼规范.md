# 红黑经验提炼规范（shared，持续迭代）

> 版本 v0.1。目标：从同事群聊和攻略文档中，稳定、可追溯地提炼「红榜（推荐）」与「黑榜（避坑）」。

## 1. 什么算红 / 什么算黑

- **红榜**：同事亲测后明确正向的具体对象或做法——值得去的景点、值得住的区域/酒店、靠谱的餐厅、
  省钱/省时/提升体验的做法、好用的包车/导游/渠道。
- **黑榜**：同事实际踩过的坑，或多源一致的负面预警——宰客、排队陷阱、名不副实、交通/天气风险、
  安全问题、预订渠道问题。**纯主观情绪吐槽、没有具体对象的不算**，避免误伤。
- 中性事实（票价、距离、营业时间）不进红黑榜，进行程正文。

## 2. 每条经验的标准结构

```
- 结论（一句话，含具体对象名）
- 红/黑：
- 类别：行前准备/交通/住宿/餐饮/景点玩法/购物消费/安全应急
- 细节：为什么推荐 / 坑的具体表现、损失（钱/时间）程度
- 黑榜绕行方案：（黑榜必填）具体怎么避开或替代
- 适用条件：季节、人群（带娃/老人）、预算等前提
- 来源：同事昵称 + 群名/文档名 + 时间或链接
- 可信度：多人验证 / 单源待核
```

## 3. 可信度与冲突处理

- **多人验证**：≥2 位同事独立提到且方向一致，优先进入总榜。
- **单源待核**：只有一人提到，标注并用公开信息核验；核验不到则保留但显式标注。
- **观点冲突**（A 推荐 B 避雷同一对象）：不做和事佬，两条都保留，写明各自的适用条件
  （例如「旺季黑、淡季红」「跟团黑、自由行红」）。
- 时间敏感信息（价格、政策、店铺是否还在）标注发言时间，超过 12 个月的必须公开核验。

## 4. 群聊提炼操作要点

1. 先拉时间线通读，再按关键词补搜：`避坑/踩雷/坑/别去/避雷/推荐/真香/必去/排队/宰客/退票/预约`。
2. 回复、跟评、表情（如大量「哈哈/同意」）可作为交叉印证信号。
3. 群内分享的文档、定位、订单截图是高价值素材，单独登记并读取本体。
4. 不臆断发言人没说过的内容；截图/转述无法确认时标「待核」。

## 5. 落榜检查（成稿前逐条过）

- [ ] 每条红黑都有具体对象，不是空泛感受
- [ ] 每条黑榜都有可执行的绕行方案
- [ ] 每条都能回溯到来源
- [ ] 冲突观点已保留并写明适用条件
- [ ] 时效信息已核验或标注时间
