## 这个工程是干什么的

结合**内网旅游群的同事讨论**、**内网旅游攻略文档**和**公开攻略**，为每一次出行生成一份可直接执行的 Markdown 行程攻略；
核心特色是沉淀同事们的**红榜经验（推荐）**与**黑榜经验（避坑）**，并在每次出行后复盘，让框架越来越贴合本人偏好。

## 目录结构（两部分，长期稳定）

```
travel-books/
├── README.md                  # 本说明
├── shared/                    # 【第一部分】共用工具：跨所有行程复用，持续迭代
│   ├── workflow.md            #   标准生产流程（采集→提炼→框架→成稿→复盘）
│   ├── sources.md             #   信息源清单（内部群/文档、外部渠道，逐步登记）
│   ├── templates/
│   │   └── 行程攻略模板.md      #   新行程攻略的初始模板（含红黑榜章节）
│   └── extraction/
│       └── 红黑经验提炼规范.md  #   如何从群聊/文档中提炼红榜与黑榜
└── trips/                     # 【第二部分】每个行程一个独立目录，互不干扰
    └── <YYYY-MM-目的地>/       #   例如 trips/2026-10-新疆/
        ├── 00-需求与约束.md     #   出行人、天数、预算、偏好、硬约束
        ├── raw/               #   原始素材快照（群聊摘录、文档导出，保留出处）
        ├── notes/             #   提炼笔记（同事经验、红黑榜候选）
        └── 行程攻略.md          #   最终成品（从 shared 模板复制后填充）
```

## 约定

1. **新建攻略**：在 `trips/` 下按 `<YYYY-MM-目的地>/` 建目录，目录结构按模板初始化；共用逻辑只引用 `shared/`，不在行程目录里重复造工具。
2. **工具迭代**：每次成稿或出行复盘后，发现模板缺字段、提炼规范有漏项、流程不顺，就回头改 `shared/`，并在 `shared/workflow.md` 的迭代记录里写一笔（版本 + 原因）。
3. **事实可追溯**：`raw/` 保留原始素材与来源链接（群名+时间、文档 URL）；攻略正文里每条同事经验都要能回溯到具体来源。
4. **红黑榜是必选项**：每份攻略必须包含红榜（值得去/值得做）与黑榜（避坑），黑榜要写清「坑是什么 + 怎么绕」。

## 当前可用信息通道

| 通道 | 用途 | 触发方式 |
|---|---|---|
| 企业知识搜索（enterprise_agentic_search） | 跨群聊/文档/会议/邮件语义检索旅游经验与攻略文档 | 按主题综合提问 |
| 飞书 IM（lark-cli im） | 精确定位旅游群、拉取群时间线、按关键词搜聊天记录 | `+chat-search` / `+chat-messages-list` / `+messages-search` |
| 飞书文档/Wiki（lark-doc / lark-wiki / lark-drive） | 读取同事分享的具体攻略文档本体 | 给定链接或搜索结果后读取 |
| 公开网络搜索（general_search / web.fetch） | 补充官方信息、票价、营业时间、公开口碑 | 外部事实核验 |

详细流程见 `shared/workflow.md`。
